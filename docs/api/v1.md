# REST API v1 (current — V1.5 + QA hardening + 2026-06-10 completion push)

> **Source of truth:** This file documents *intent*. Live API docs are auto-generated at `GET /docs` (Swagger UI) and `GET /openapi.json`. When they disagree, the live docs win and this file gets fixed.

Base URL: `https://api.anjaneya-ott.example/v1` (dev: `http://localhost:8000/v1`)
Auth: `Authorization: Bearer <access_token>` unless marked **public**.

## The `X-Profile-Id` header (active profile)

All user-scoped endpoints (continue-watching, My List, reactions, progress, history, `/v1/home`, playback) accept an optional `X-Profile-Id` header naming the active profile.

Contract:
- The header is client-supplied and **never trusted on its own**: the profile is only honoured when it exists AND belongs to the authenticated user.
- No header, a garbage value, or someone else's profile id all quietly degrade to the legacy "no profile" (NULL) scope — never an error — so stale frontend localStorage can't lock a user out.
- Watchlist / watch-progress / reaction rows are scoped per profile (migration `8c4f72d1e6a3`); rows written before profiles existed live in the NULL scope and stay reachable without the header.

**Kid profiles:** when the active profile has `kind="kid"`, home rows are filtered to U-rated titles (NULL `age_rating` fails closed), and **playback of any non-U title is rejected with 403**:

```json
{"error": {"code": "kid_profile_restricted", "message": "This title isn't available on a kids profile."}}
```

This 403 applies to both `/v1/titles/{id}/play` and `/v1/episodes/{id}/play`. Known gap: full catalog browse/search is not yet kid-filtered — playback is the hard gate.

## Auth

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/v1/auth/signup` | public | Create account. Body: `{email, password, full_name?}`. Returns `{tokens, user}`. |
| POST | `/v1/auth/login` | public | Email + password. Returns access + refresh tokens. |
| POST | `/v1/auth/refresh` | public | Body: `{refresh_token}`. Rotates the refresh; reuse-detection burns the family. |
| POST | `/v1/auth/logout` | user | Revokes the family the refresh token belongs to. |
| POST | `/v1/auth/change-password` | user | Body: `{current_password, new_password}` (new: 8–128 chars, `extra="forbid"`). Verifies the current password (401 `invalid_credentials` if wrong), revokes **every other session** (all refresh families + session_version bump) and returns a fresh `TokenPair` so this session stays logged in — the client must swap its stored tokens. |
| GET | `/v1/auth/me` | user | Current user profile (no password_hash, no internal fields). |

Login and signup are rate-limited per client IP (login 10/min, signup 5/min) — over-limit requests get 429 with a `Retry-After` header.

### Playback gating rules

A user has an "active" subscription (allowed to play paid content) iff:
- `status='active'` AND `current_period_end > now()`

A user with an expired/cancelled/pending row gets 402 on paid content. Free content (see `is_free` below) is always playable.

## Payments

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/v1/payments/verify` | user (or checkout token) | After Razorpay Checkout JS completes on the frontend, POST `{razorpay_order_id, razorpay_payment_id, razorpay_signature}` here to verify HMAC and immediately flip the sub to `active`. The webhook is still authoritative if this is missed. |

Defence in depth before activating a subscription:
1. HMAC signature check (proves the values came from Razorpay).
2. The payment is fetched from Razorpay's API and must have `status == "captured"` AND an amount equal to the plan price — 400 `payment_not_captured` / `amount_mismatch` otherwise. A valid signature on an authorized-but-not-captured or short-paid payment does not unlock access.

Auth: either a normal Bearer access token, or (dev `/test-checkout` flow only) a single-purpose **checkout token** — 10-min TTL, `purpose='checkout'`, scoped to exactly one order, rejected by every other endpoint. This replaced putting the user's real access token in the checkout URL. The `/test-checkout` page itself is not registered when `APP_ENV=prod`.

## Playback

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/v1/titles/{id}/play` | user + entitled | Movie playback ticket. Returns 402 if paid + no sub, 409 if series (use episode endpoint), 409 if no playable asset, 403 `kid_profile_restricted` if the active profile is a kid and the title isn't U-rated. |
| GET | `/v1/episodes/{id}/play` | user + entitled | Episode playback ticket. 404 if parent series is archived/removed. Same 403 kid gate as movies (checked against the parent series rating). |

### PlaybackTicket response shape

```json
{
  "manifest_url": "https://s3.us-east-005.backblazeb2.com/.../master.mp4?X-Amz-Signature=...",
  "token": "eyJ0eXAi...",
  "expires_at": "2026-06-03T13:00:00Z",
  "ref_type": "title",
  "ref_id": 5,
  "resume_at_sec": 450,
  "total_sec": 5400
}
```

`resume_at_sec` is the user's prior progress (null on first play). `total_sec` is the player progress bar's max. The frontend seeks to `resume_at_sec` immediately on play start — saves a round trip to `/v1/me/continue-watching`.

Manifest TTL is **15 minutes**. Long enough to start; player refreshes the URL when it expires.

## Home / browse rows

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/v1/home` | user (optional — anon gets the public-row subset) | `?country=IN` for Top-in-country row. |
| GET | `/v1/home/genres` | public | Same as `/v1/genres` (legacy alias). |

Row kinds the frontend renders (empty rows are omitted):
- `continue_watching` — most-recent in-progress, capped 20
- `my_list` — watchlist, `added_at DESC`, capped 50
- `new_releases` — published in last 30 days, capped 20
- `trending_now` — top by view_count, capped 20
- `top_in_country` — top by view_count, country-filtered, capped 10
- `because_you_watched:{seed_title_id}` — for each of the user's 1-2 most-recent finished titles, titles sharing ≥1 genre (excludes already-watched)

Anonymous users see: `new_releases`, `trending_now`, `top_in_country` (if `country` param given).

Personalized rows are per-profile (`X-Profile-Id` is part of the cache key). Kid profiles see only U-rated titles in every row.

## Webhooks

| Method | Path | Description |
|---|---|---|
| POST | `/v1/webhooks/razorpay` | Razorpay event. Signature-verified (HMAC-SHA256 against `RAZORPAY_WEBHOOK_SECRET`). Idempotent via `X-Razorpay-Event-Id` header (deduped against `webhook_events` table). Events older than 10 min rejected as stale (replay window). **Strict:** `created_at` in the body and the `X-Razorpay-Event-Id` header are required — 400 `missing_created_at` / `missing_event_id` otherwise, because without them the replay window and idempotency checks would be silently skipped. |

**Events handled:**
- Orders mode (default): `payment.captured`, `payment.failed`, `order.paid`
- Subscriptions mode (requires Razorpay business KYC): `subscription.activated/authenticated/charged/cancelled/completed/halted/paused/pending`

## Error envelope

```json
{
  "error": {
    "code": "invalid_credentials",
    "message": "Email or password is incorrect.",
    "request_id": "req_01HXY..."
  }
}
```
Validation errors include a `details` array of field-level issues.
