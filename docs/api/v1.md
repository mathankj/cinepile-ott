# REST API v1 (current — V1.5 + QA hardening)

> **Source of truth:** This file documents *intent*. Live API docs are auto-generated at `GET /docs` (Swagger UI) and `GET /openapi.json`. When they disagree, the live docs win and this file gets fixed.

Base URL: `https://api.anjaneya-ott.example/v1` (dev: `http://localhost:8000/v1`)
Auth: `Authorization: Bearer <access_token>` unless marked **public**.

---

## Subscriptions

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/v1/plans` | public | List active plans. |
| GET | `/v1/subscriptions/me` | user | User's most-recent subscription **regardless of status** (so the frontend can show 'pending', 'expired', 'cancelled' banners). |
| POST | `/v1/subscriptions` | user | Subscribe. Body: `{plan_code}`. **Idempotent**: if a pending sub for the same plan exists, returns it instead of creating a new Razorpay order. | POST | `/v1/subscriptions/cancel` | user | Cancel at period end. |

### Playback gating rules

A user has an "active" subscription (allowed to play paid content) iff:
- `status='active'` AND `current_period_end > now()`

A user with an expired/cancelled/pending row gets 402 on paid content. Free content (see `is_free` below) is always playable.

|---|---|---|---|

### Per-title fields the frontend should know about

| Field | Type | Meaning |
|---|---|---|
| `is_free` | bool | When true, anyone can play this title (no subscription). Frontend renders a "FREE" badge. |
| `status` | string | `draft` \| `scheduled` \| `published` \| `archived` \| `removed` |
| `publish_at` | datetime\|null | When a `scheduled` title will go live |
| `view_count` | int | Denormalized counter; used for Trending row |

## Playback

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/v1/titles/{id}/play` | user + entitled | Movie playback ticket. Returns 402 if paid + no sub, 409 if series (use episode endpoint), 409 if no playable asset. |
| GET | `/v1/episodes/{id}/play` | user + entitled | Episode playback ticket. 404 if parent series is archived/removed. |

### PlaybackTicket response shape

```json
{
  "manifest_url": "https://s3.us-east-005.backblazeb2.com/.../master.mp4?X-Amz-Signature=...",
  "token": "eyJ0eXAi...",
  "expires_at": "2026-06-03T13:00:00Z",
  "ref_type": "title",
  "ref_id": 5,
  "resume_at_sec": 450,
  "total_sec": 5400
}
```

`resume_at_sec` is the user's prior progress (null on first play). `total_sec` is the player progress bar's max. The frontend seeks to `resume_at_sec` immediately on play start — saves a round trip to `/v1/me/continue-watching`.

Manifest TTL is **15 minutes**. Long enough to start; player refreshes the URL when it expires.

## Home / browse rows

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/v1/home` | user (optional — anon gets the public-row subset) | `?country=IN` for Top-in-country row. |
| GET | `/v1/home/genres` | public | Same as `/v1/genres` (legacy alias). |

Row kinds the frontend renders (empty rows are omitted):
- `continue_watching` — most-recent in-progress, capped 20
- `my_list` — watchlist, `added_at DESC`, capped 50
- `new_releases` — published in last 30 days, capped 20
- `trending_now` — top by view_count, capped 20
- `top_in_country` — top by view_count, country-filtered, capped 10
- `because_you_watched:{seed_title_id}` — for each of the user's 1-2 most-recent finished titles, titles sharing ≥1 genre (excludes already-watched)
- `genre:{slug}` — for each of the user's top genres by play count

Anonymous users see: `new_releases`, `trending_now`, `top_in_country` (if `country` param given).

## Webhooks

| Method | Path | Description |
|---|---|---|
| POST | `/v1/webhooks/razorpay` | Razorpay event. Signature-verified (HMAC-SHA256 against `RAZORPAY_WEBHOOK_SECRET`). Idempotent via `X-Razorpay-Event-Id` header (deduped against `webhook_events` table). Events older than 10 min rejected as stale (replay window). |

**Events handled:**
- Orders mode (default): `payment.captured`, `payment.failed`, `order.paid`
- Subscriptions mode (requires Razorpay business KYC): `subscription.activated/authenticated/charged/cancelled/completed/halted/paused/pending`

## Error envelope

```json
{
  "error": {
    "code": "invalid_credentials",
    "message": "Email or password is incorrect.",
    "request_id": "req_01HXY..."
  }
}
```
Validation errors include a `details` array of field-level issues.
